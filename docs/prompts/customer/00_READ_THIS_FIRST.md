# Project Goal

Build a production-ready enterprise e-commerce platform for **HOPSY PLAZA**, a Nigerian electronics retailer.

The Customer Website and Admin Dashboard are deployed separately using different URLs while sharing the same backend infrastructure.

The finished product must be suitable as a professional portfolio project and production-ready foundation.

---

# Design Philosophy

The interface must feel professionally designed by an experienced product designer.

It should be comparable in quality to leading electronics retailers such as:

* Apple
* Samsung
* Sony
* Bose
* Best Buy
* Framework

Do not imitate these websites.

Instead, study the design principles that make them successful and create a unique HOPSY PLAZA identity.

---

# Forbidden Design Patterns

Never introduce:

* AI-looking layouts
* Generic Tailwind templates
* Giant hero sections
* Glassmorphism
* Neon gradients
* Cartoon illustrations
* Floating stickers
* Floating "live" indicators
* Random glowing cards
* Excessive gradients
* Oversized headings
* Poor spacing
* Inconsistent typography
* Inconsistent iconography
* Unbalanced layouts

Every page should appear intentionally designed rather than AI generated.

---

# Engineering Principles

Always prioritize:

* Reusable components
* Type safety
* Clean architecture
* Separation of concerns
* Maintainability
* Accessibility
* Performance
* Scalability

Avoid duplicated code.

Avoid hardcoded values.

Avoid unnecessary abstraction.

---

# UI Standards

Every screen must include:

* Loading states
* Empty states
* Error states
* Responsive layouts
* Keyboard accessibility
* Proper focus management
* Smooth premium animations
* Consistent spacing
* Consistent typography
* Consistent icon usage

---

# Implementation Rules

Implement only the requested task.

Do not modify unrelated modules.

Do not change database structures unless the task requires it.

Do not redesign previously approved components without justification.

Preserve consistency across the entire project.

---

# Code Quality Requirements

Every implementation must:

* Compile successfully.
* Pass linting.
* Follow TypeScript best practices.
* Follow Next.js best practices.
* Follow Tailwind best practices.
* Be modular.
* Be production ready.

---

# Validation Checklist

Before marking a task complete, verify:

* Requirements implemented.
* Business rules followed.
* Responsive on all screen sizes.
* Accessible.
* Performance optimized.
* No console errors.
* No TypeScript errors.
* No lint errors.
* No duplicated logic.
* No placeholder content.
* No AI-generated design patterns.

Only mark the task complete after every item has been verified.

# Definition of Success

The implementation is successful when the completed feature integrates seamlessly with the rest of the platform, follows every project document, demonstrates enterprise-grade engineering practices, and appears as though it was crafted by a senior product team rather than generated from a generic template.
