# HOPSY PLAZA Electronics E-Commerce Platform

**Version:** 1.0

**Status:** Project Foundation

---

# 1. Project Overview

HOPSY PLAZA Electronics E-Commerce Platform is a production-grade, enterprise-level retail platform designed for a real electronics business operating in Nigeria while supporting international customers.

The project consists of two independently deployed web applications sharing a centralized backend, authentication system, database, and business logic.

The objective is not simply to create an online store, but to build a scalable digital commerce ecosystem that reflects modern software engineering practices, premium product design, and maintainable architecture.

This project will serve both as a production-ready business solution and a portfolio-quality showcase demonstrating enterprise architecture, clean code, excellent user experience, security, scalability, accessibility, and performance.

# 8. Design Philosophy

The interface must communicate professionalism, trust, and premium quality.

Design inspiration may be informed by premium retail experiences such as Apple, Samsung, Best Buy, Sony, Framework, and Bose, while maintaining HOPSY PLAZA's own branding and identity.

The application must never appear to be AI-generated.

---

# 9. Prohibited Design Patterns

The following are prohibited throughout the project:

* Generic AI-generated layouts
* Generic Tailwind starter templates
* Oversized hero sections
* Decorative floating cards
* Floating "live" indicators
* Random glowing elements
* Excessive gradients
* Glassmorphism
* Cartoon illustrations
* Decorative stickers
* Fake analytics
* Placeholder statistics
* Empty whitespace without purpose
* Inconsistent spacing
* Random animations
* Unnecessary visual effects

Every visual element must serve a functional purpose.

# 13. AntiGravity Execution Instructions

Before beginning **any** task, AntiGravity must:

1. Read this manifest and every document relevant to the current task.
2. Analyze the existing project structure, source code, completed features, and design system to maintain consistency.
3. Thoroughly inspect **all available AntiGravity skills**. Do not assume previously used skills are appropriate for the current task.
4. Evaluate the purpose and strengths of each available skill.
5. Select **only** the skill or combination of skills that best matches the current objective. Combine skills when it improves quality (for example, architecture, UI/UX, frontend, backend, accessibility, or QA), but avoid unrelated skills.
6. Create an implementation plan before generating code.
7. Produce production-quality work that integrates cleanly with the existing project.
8. Perform a self-review, resolving inconsistencies, responsiveness issues, accessibility concerns, and obvious defects before considering the task complete.
9. Never replace existing high-quality implementations with generic alternatives.
10. Treat every task as part of a single, coherent product rather than an isolated feature.

The project will be considered successful when:
